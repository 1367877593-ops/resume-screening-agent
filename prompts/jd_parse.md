## 规则

1. 每条要求必须是**可以对着简历回答「满足 / 部分满足 / 不满足」的具体事项**。
   「有良好的沟通能力」这类无法从简历证实的表述不要列入。
   把「熟悉 Python 和 SQL」这类复合要求拆成两条。
2. `requirement_id` 用 `R1`、`R2`、`R3` 顺序编号。
3. `weight` 填 1-10 的相对重要性，**不需要凑成 100**，系统会自行归一化。
   JD 里反复强调或列在前面的要求给高权重。
4. `is_hard` 只在 JD 明确表达了不可协商的门槛时为 true，
   例如「本科及以上学历」「三年以上经验」「必须持有 XX 证书」。
   带「优先」「加分」「最好」字样的一律为 false。
   **谨慎使用**：标为 true 意味着不满足即淘汰，不看总分。
5. `category` 从 学历 / 经验 / 技能 / 项目 / 其他 中选一个。
6. 要求项控制在 5-15 条。
